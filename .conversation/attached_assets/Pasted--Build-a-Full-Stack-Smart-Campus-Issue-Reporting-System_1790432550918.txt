# Build a Full-Stack Smart Campus Issue Reporting System

Create a modern, responsive, production-style web application called **CampusCare** — a centralized smart campus issue reporting and resolution platform.

The purpose of the application is to allow students and staff to report campus problems, automatically categorize and prioritize them, allow administrators to manage them, and provide transparent real-time status tracking.

The website should look polished enough for a college hackathon demonstration.

---

# 1. Core Concept

The application should support this complete workflow:

**Student/Staff → Report Issue → AI Categorization → Priority Detection → Admin Review → Status Updates → Resolution → Transparent Tracking**

Example:

A student reports:

> "There is water leaking from the ceiling in Block B, Room 304 and the floor is getting flooded."

The system should automatically determine:

* Category: **Plumbing**
* Priority: **High**
* Location: **Block B → Floor 3 → Room 304**
* Status: **Reported**

The administrator can then change:

**Reported → In Progress → Resolved**

The student should be able to track the issue throughout the entire process.

Implement automatic categorization based on the issue description.

Example:

**Category: Electrical**

> "Water is leaking from the bathroom ceiling."

# 6. AI Priority Detection

Automatically assign priority based on the description.

Priority levels:

### Critical

Immediate safety/security risk.

Examples:

* Exposed electrical wires
* Fire
* Major flooding
* Gas leak
* Serious security issue
* ragging

### High

Requires urgent attention.

Examples:

* Large water leak
* Major power failure
* Broken security equipment

### Medium

Important but not immediately dangerous.

Examples:

* Broken classroom fan
* Projector not working
* Wi-Fi issue

### Low

Minor inconvenience.

Examples:

* Broken chair
* Small cosmetic damage
* Minor maintenance issue

Display:

🔴 Critical
🟠 High
🟡 Medium
🟢 Low

AI should explain the reason briefly.

Example:

> **Priority: High**
>
> Reason: Water leakage may cause property damage and create a safety hazard.

Administrators must be able to manually change the priority.

# 7. Duplicate Issue Detection

Implement smart duplicate detection.

When a new issue is submitted, compare:

* Description
* Category
* Location
* Existing issues

> ⚠️ Similar issue detected

Example:

> A similar electrical issue was reported in Block A, Room 204.

Show:

* Existing issue ID
* Description
* Location
* Current status

Give the user two options:

**View Existing Issue**

or

**Submit Anyway**

Do not prevent submission completely.

If real AI/semantic similarity is unavailable, implement a basic keyword/location similarity system as a fallback.
